# Project Brief — Tabs Component

## Original Brief

In this challenge, you will build a versatile tabs component as part of a design system. These components will be essential for making selections across various projects and apps found within the platform.

### Component States, Variants, and Properties

- **States:** Implement and style the component to reflect different states – initial/default, hover, and focus.

### Implementation Requirements

- **Design fidelity:** Aim to follow the design as closely as possible. All elements in the design should be present, using the specified text color, font size, font weight, spacing, dimensions, etc.
- **Switching between tabs:** Clicking on the tabs should switch between the tabs and display the associated panel contents.
- **Cross-browser compatibility:** Check that your solution works for major browsers including Chrome, Firefox, and Safari.
- **[Stretch] Performance optimization:** Optimize image assets and code for quick load times.
- **[Stretch] Accessibility and semantics:** Follow best practices for web accessibility, using semantic HTML and ARIA roles where necessary and proper alt tags for images.

## Implementation Checklist

- [ ] HTML structure with correct semantic elements and ARIA tablist pattern
- [ ] Tab list renders all tabs
- [ ] Active tab has distinct visual state (underline/indicator)
- [ ] Hover and focus states styled correctly
- [ ] Clicking a tab switches the active tab and shows associated panel
- [ ] Inactive panels are hidden
- [ ] Design fidelity: colors, typography, spacing, dimensions match Figma
- [ ] Cross-browser tested (Chrome, Firefox, Safari)
- [ ] [Stretch] ARIA roles: `role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected`, `aria-controls`
- [ ] [Stretch] Keyboard navigation (Arrow keys between tabs, Tab into panel)
